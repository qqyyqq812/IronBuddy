# 用户手册

本章是 IronBuddy 的功能总览：把所有可见功能、所有可切换的模式、所有可触发的能力一次性讲清楚。后面的章节再分别展开规划、数据库、语音、调试台、部署等细节。

## 一、项目定位

IronBuddy 不只是一个跑在板端的"动作计数器"。它的目标是把**视觉骨架**、**表面肌电**、**有限状态机**、**轻量神经网络**、**语言模型**、**语音对话**这些原本各自为政的模块，串成一条**实时、可解释、可降级**的闭环：

- **实时**：USB 摄像头 → 板端 NPU → 骨架关键点 → 角度计算 → rep 判定 → 屏幕反馈，全链路端到端 < 200 ms
- **可解释**：每一次 rep 的判定都有可查的来源，几何角度、肌电激活、模型置信度全部入库
- **可降级**：肌电断开自动回退到纯视觉；云端断开自动回退到本地 NPU；LLM 超时回退到本地模板回复；语音失败可用按钮替代

整个系统**离线优先**：板子断网，本地视觉 + 本地 FSM + 本地疲劳积分 + 本地数据库依然能完成完整训练；联网时云端 GPU、DeepSeek、飞书、百度 TTS 才作为可选增强加入。

## 二、四种核心模式（两组开关的笛卡尔积）

主界面顶部有**两个开关**，组合出四种工作模式：

|              | **纯视觉 (pure_vision)** | **视觉+传感 (vision_sensor)** |
|--------------|--------------------------|--------------------------------|
| **深蹲**     | FSM 几何判定，无 GRU 点评  | FSM 几何 + GRU 三分类点评       |
| **哑铃弯举** | FSM 几何判定，无 GRU 点评  | FSM 几何 + GRU 三分类点评       |

### 2.1 动作开关（深蹲 ↔ 哑铃弯举）

切换"动作"会**同时切换三件事**：

1. **使用的 FSM 类**：深蹲走 `SquatStateMachine`，弯举走 `DumbbellCurlFSM`，两个 FSM 完全独立、互不污染
2. **取哪个角度**：深蹲取**膝关节角度**（髋-膝-踝三关节夹角），站立约 180°、深蹲底部约 90° 是一次合格 rep；弯举取**肘关节角度**（肩-肘-腕三关节夹角），自然下垂约 150° 以上、弯举顶端约 50° 是一次合格 rep
3. **中间骨架小人的形态**：深蹲会蹲下站起、弯举会屈臂伸臂，动作切换时旧形态会立刻清除，不会留残影

切换方式：
- 主页面顶部"动作"分段控件，点击切换
- 语音说"切换到深蹲" / "切换到弯举"
- 设置面板下拉框选择

### 2.2 模式开关（纯视觉 ↔ 视觉+传感）

切换"模式"只决定**判断器（GRU 三分类）是否启动**：

- **纯视觉模式**：只用骨架角度判定一次 rep 是"标准"还是"违规"（两分类）。不需要肌电，断开传感器也能跑。**适合没接传感器的演示、快速试用、或传感器掉电时的降级**。
- **视觉+传感模式**：在 FSM 完成一次 rep 时，把这一次 rep 内 30 帧的骨架角度 + 角速度 + 主发力肌肉激活 + 代偿肌肉激活等 7 维特征送入轻量 GRU 模型，输出**标准 / 代偿 / 错误**三分类。主页面中央"判断中"圆圈会亮起、给出分类结果。**适合有 ESP32 肌电传感器且已贴片到目标肌群**。

切换方式：
- 主页面顶部"模式"分段控件
- 语音说"切换到纯视觉" / "切换到视觉加传感"

不管哪种模式，FSM 计数都正常工作。GRU 只在视觉+传感模式跑，纯视觉下判断器整个隐藏。

## 三、视觉后端切换：本地 NPU ↔ 云端 GPU

视觉骨架推理有两种后端可在线热切换：

### 3.1 本地 NPU（YOLOv5-Pose RKNN，默认）

- 模型在板端 RK3399ProX 的 NPU 上推理，**完全离线**
- 量化为 uint8，关键点置信度数值偏低（典型 0.08-0.2），系统已自适应过相关阈值
- 端到端延迟 < 60 ms，帧率约 14 fps
- 主页面"视觉后端"下拉框选**本地 NPU (YOLOv5-Pose)**

### 3.2 云端 GPU（RTMPose RTX 系列，可选）

- 模型在云端 GPU 服务器上推理，由板端通过 SSH 隧道访问
- 关键点更准、置信度更高，适合**精度敏感**的演示或数据采集
- 端到端延迟约 80-150 ms（含网络），帧率约 14 fps
- 切换时如果隧道未建立，系统会自动尝试 SSH 自愈
- 主页面"视觉后端"下拉框选**云端 RTMPose**

两种后端使用同一套下游处理（FSM、GRU、疲劳积分），切换时**主视频流也会自动重连**，整个切换约 1-2 秒生效。

## 四、训练计划与组间总结

IronBuddy 把"今天该练什么"这件事交给 DeepSeek。主页面"智能规划"区域负责完整的训练计划生命周期：

### 4.1 智能计划生成

- 系统读取**最近 7 天训练记录**、**当前疲劳水平**、**用户偏好**等上下文
- 调用 DeepSeek 流式 API，前端实时渲染思考过程（思考链可见）
- 输出**计划卡片**：包含动作、组数、每组次数、目标疲劳积分、建议强度、注意事项
- 用户可一键采纳，进入训练态

### 4.2 组间总结

- 每完成一组（达到目标 rep 数或主动停止），系统自动触发**组间总结**弹窗
- 总结内容包含**本组合格数、违规数、代偿数、平均角度、疲劳值变化、下一组建议**
- 总结由 DeepSeek 生成，限时 30 秒，超时自动回退到本地模板
- 用户可手动跳过、或等待自动消失

### 4.3 训练报告

- 整次训练结束（全部组数完成或长时间无新 rep），系统生成**训练报告**
- 报告包含本次训练概览 + 跨日趋势对比 + 下一次训练建议
- 报告可一键推送到飞书会话（详见语音控制章节）

### 4.4 离线降级

DeepSeek 不可用时：
- 计划生成回退到**预设模板**（按动作 × 难度组合）
- 组间总结回退到**规则引擎**（基于 rep 计数和疲劳积分）
- 训练报告仍可生成，只是不含 AI 点评

## 五、疲劳值模型

主页面中央常驻一个**疲劳积分**指示器（默认上限 600，可在设置面板里改）。疲劳积分的设计目标是**反映"目标肌群的累积有效激活剂量"**，而不是简单计数。

### 5.1 三档可切换模型

| 版本 | 触发节奏 | 适用场景 |
|------|---------|---------|
| v1（dose_integral_v1） | 每 rep 完成时一次性叠加 | 纯视觉、传感器无信号 |
| **v2（dose_integral_v2，默认）** | 每 rep 一次性叠加，含 MDF/MNF 频域加权、ROM 钟形评分、动作类型查表 | 有肌电、想反映"动作越接近标准、激活剂量越高"的语义 |
| v3（ODE Liu 2002） | 视觉骨架率（约 14Hz）逐帧 ODE 在线积分 | 想要平滑曲线 / 研究用，需 env 变量启用 |

v2 是默认上线版本。v3 ODE 是研究方向（专利交底相关），通过环境变量 `IRONBUDDY_FATIGUE_V3=1` 切换。

### 5.2 疲劳如何影响行为

- 训练计划生成会读取**当日已累积疲劳**，按比例下调建议强度
- 单次训练疲劳达上限会触发**强制提醒**（语音 + 横幅）
- 数据库 `daily_summary` 每日汇总疲劳峰值，用于跨日趋势

## 六、动作判定的两层

IronBuddy 对一次 rep 的判定走两层流水线：

### 6.1 第一层：FSM 几何判定（永远开）

- 输入：每帧的骨架关键点
- 角度计算（深蹲取膝、弯举取肘），跨帧平滑 + 中值滤波，剔除单帧异常
- 状态转移：站立 → 下蹲（或屈臂）→ 底部 → 起立（或伸臂）→ 计为一次 rep
- 一次合格 rep 的**最低角度**必须低于该动作的标准阈值（深蹲 90°、弯举 50°）；最低角度高于阈值则计为"违规"
- 该层结果就是主页面右下角"标准 / 违规 / 代偿"三个累计计数

### 6.2 第二层：GRU 三分类（仅视觉+传感模式）

- 输入：一次 rep 内 30 帧 × 7 维特征
- 7 维包括：角速度、角度、角加速度、目标肌肉激活、代偿肌肉激活、最低角度归一化值、ROM 归一化值
- 输出：标准 / 代偿 / 错误，附置信度
- 主页面中央"判断中"圆圈在 rep 完成后约 50 ms 内变成具体分类
- 该层**仅在视觉+传感模式启动**；纯视觉模式下整个判断圈隐藏

两层是**互补**的：FSM 给"是否完成"，GRU 给"完成质量"。FSM 失败则整个 rep 不算；FSM 通过但 GRU 判错则计入"代偿"。

## 七、语音对话

完整命令列表、唤醒方式和模糊匹配规则见 [04 语音控制与飞书周报](04_语音控制与飞书周报.md)。这里只列功能要点：

- **唤醒**：默认唤醒词"教练"。两段式："教练" → 系统应答"嗯" → 用户说命令；单轮式：一句话同时包含唤醒词和命令（"教练帮我切换到深蹲"）
- **命令**：动作切换、模式切换、静音 / 解除静音、查询当前次数、训练计划采纳、飞书推送、关机
- **降级**：麦克风、STT 或扬声器任一不可用时，可改用主页面手动按钮完成同一闭环
- **静音逻辑**：静音态下系统不主动播报，但**违规警报**仍会强制播一次（动作安全优先）

## 八、飞书周报

- 训练结束后系统会自动把"训练战报卡片"推送到指定的飞书会话
- 卡片包含本次训练总览、动作分布、疲劳曲线、AI 点评、跨日对比
- 推送可在主页面**手动触发**（点"飞书战报"按钮）或由语音命令触发（"教练，推送飞书周报"）
- 需要在板端 `.env` 配置飞书应用凭据；外网不可用时退回本地预览

## 九、数据持久化

板端使用 SQLite + WAL 模式存储训练数据，8 张关键表：

- `training_sessions`：每次训练的开始时间、结束时间、汇总
- `rep_events`：每一次 rep 的角度、判定来源、模型分类
- `daily_summary`：每日训练量、疲劳峰值、平均 ROM
- `llm_log`：训练计划、组间总结、问答的完整链路
- `user_config`：用户偏好、疲劳上限、语音设置
- `model_registry`：已加载的视觉 / 教练模型版本登记
- `fatigue_v3_snapshots`：v3 ODE 每个 rep 的疲劳快照（研究用）
- `event_log`：系统事件审计

默认开启**延迟落盘**（`IRONBUDDY_DB_DEFER_WRITES=1`），训练过程中所有 rep 暂存内存，按 STOP 后批量写库。这避免 WAL 文件在 demo 中频繁膨胀。

完整数据库使用方式见 [03 数据库页](03_数据库与训练趋势.md)。

## 十、运行环境约束

板端是 **Toybrick RK3399ProX**：

- 6 核 ARM big.LITTLE CPU + 3 TOPS NPU
- Python 3.7（**禁用** `X | None` 语法、`match/case`、`:=`、`pandas`）
- 共享内存 `/dev/shm` 用于跨进程 JSON IPC
- ALSA 直驱音频，HDMI 直连显示器
- USB 摄像头 MJPG 640×480 是延迟和准确率的最优点

外部组件：

- **ESP32-S3** 4 通道肌电采集，BLE 配对后通过 UDP 发到板端 8080 端口
- **云端 GPU** 提供 RTMPose HTTP 推理接口，板端通过 SSH 隧道访问
- **DeepSeek** REST API 提供 LLM 能力，SSE 流式输出
- **百度 AipSpeech** 提供 TTS + STT
- **飞书 OpenCloud** 提供消息推送

任意一个外部组件不可用，本地都能独立完成训练闭环。
