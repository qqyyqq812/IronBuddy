# 语音控制与飞书周报

IronBuddy 的语音对话不依赖深度学习的命令理解，而是用**关键词模糊匹配**做硬编码命令路由：百度 ASR 把声音转成文字，再由板端教练守护进程在文字里搜关键词，命中就直接执行对应动作。这样设计的好处是**离线可控、毫秒级响应、不会胡乱回答**。

本章把唤醒流程、所有可识别的语音命令、识别容错机制和飞书推送一次性讲清楚。

## 一、两种唤醒方式

主唤醒词是**"教练"**。你有两种触发对话的方式：

### 方式一：两段式唤醒（更稳定）

1. 用户说："**教练**"
2. 系统约 300 毫秒内播一声短促应答："**嗯**"
3. 应答播完后系统打开二次录音窗口（默认 6 秒）
4. 用户在窗口期说出真正的命令："切换到深蹲" / "帮我静音" / ...
5. 系统执行命令并回复，整轮结束后**自动回到等待唤醒态**

这种方式适合**指令比较长、思考时间不够、或者环境噪声大**的场景。两段之间有明确的应答提示，体验更自然。

### 方式二：单轮唤醒（更快）

直接说一句话，**同时包含唤醒词和命令**，例如：

- "**教练**，帮我切换到深蹲"
- "**教练**静音"
- "**教练**今天我该怎么练"
- "**教练**发训练总结到飞书"

系统识别到这句话里含"教练"后，会把"教练"剥离掉，把剩下的部分直接当命令处理，**不打开二次录音窗口**。整轮在 1 秒内完成，回声小，效率高。

### 哪个流程更适合

- 嘈杂环境、需要思考下一句说什么：**两段式**
- 已经想好要说的命令、追求最快响应：**单轮**

两种方式系统都接受，不需要切换设置。

## 二、所有可识别的语音命令

下表是板端教练守护进程**实际硬编码识别**的所有命令。每一行的"识别关键词"列出系统真正在文字里搜索的子串，只要用户说话里**包含任意一个**，就会触发对应动作。

### 2.1 模式切换类

| 意图 | 你可以说 | 系统会做 |
|------|---------|---------|
| 切换到深蹲 | 切换到深蹲 / 切到深蹲 / 进入深蹲 / 深蹲模式 / 改成深蹲 | 切换 FSM 到 SquatStateMachine，骨架角度改读膝关节，主页面动作开关移到深蹲位 |
| 切换到弯举 | 切换到弯举 / 切到弯举 / 进入弯举 / 弯举模式 / 切换哑铃 / 切换动作（默认对侧）| 切换 FSM 到 DumbbellCurlFSM，角度改读肘关节，主页面动作开关移到弯举位 |
| 切换到纯视觉 | 纯视觉 / 视觉模式 | 关闭 GRU 三分类判断器，只走 FSM 几何判定 |
| 切换到视觉+传感 | 视觉加传感 / 视觉传感 / 传感模式 / 传感器模式 / 加传感 / 混合模式 / 融合模式 / 全模式 | 开启 GRU 三分类判断器，rep 完成后会给"标准/代偿/错误"评价 |

### 2.2 静音类

| 意图 | 你可以说 | 系统会做 |
|------|---------|---------|
| 静音 | 静音 / 闭嘴 / 教练静音 / 别说话 / 别吵 | 立刻打断当前播报，进入静音态。静音态下只有违规警报会继续播 |
| 解除静音 | 解除静音 / 可以说话 / 你可以说话 / 恢复对话 / 恢复说话 / 继续说话 / 打开声音 / 开声 / 恢复声音 | 退出静音态，恢复正常对话和提示音 |

注意：违规警报（如"动作不标准"）即使在静音态也会强制播一次，这是**动作安全优先**的设计。

### 2.3 训练查询与控制类

| 意图 | 你可以说 | 系统会做 |
|------|---------|---------|
| 查询当前次数 | 多少个 / 几个 / 完成度 / 成绩 / 报数 / 做了多少 / 干了多少 / 多少次 / 练了多少 | 读取当前 FSM 状态，口头报出"当前深蹲达标 X 个，违规 Y 个" |
| 采纳今日计划 | 开始训练 / 开始今天训练 / 开始今日训练 / 采纳方案 | 把当天 DeepSeek 生成的训练计划写入板端，进入训练态 |

### 2.4 飞书推送类

只要听到"飞书"近音字（飞书 / 非书 / 飞出 / 菲书 / 腓书 / 废书 / 飞输 / 肥书）或"推送"动词系列（推送 / 推到 / 推送到 / 发送到 / 发到 / 发给），系统就会触发飞书推送。具体推送类型由其他关键词决定：

| 意图 | 关键词 | 系统会做 |
|------|--------|---------|
| 推送训练战报 | 总结 / 汇报 / 战报 / 飞书报告 / 飞书总结 / 生成报告 / 训练结果 / 训练总结 / 训练报告 / 战况 / 成绩报告 | 调取最近一次训练 + 历史趋势 + AI 点评，生成飞书卡片推送 |
| 推送训练规划 | 规划 / 计划 / 发飞书 / 发消息 | 调取长期记忆，生成下一阶段训练规划推送飞书 |
| 推送提醒 | 警告 / 提醒 / 超载 / 报警 | 推送系统超载警示卡片 |

例句：
- "教练，推送训练总结到飞书"
- "教练，把今天的成绩发到飞书"
- "教练，规划下一周的训练发飞书"

### 2.5 系统类

| 意图 | 你可以说 | 系统会做 |
|------|---------|---------|
| 关机 | 关机 | 板端执行 shutdown 流程（含数据库 checkpoint 和 session 收尾），约 5 秒后掉电 |
| 再见 | 再见教练 | 优雅结束当前训练会话，写入数据库 |

## 三、识别容错（关键词模糊匹配）

百度 ASR 在嘈杂环境或方言口音下容易把字识错。教练守护进程内部维护了一张**同音字 / 近音字容错表**，让常见错识也能命中。

### 3.1 唤醒词容错

`教练` 的容错列表：`教练 / 叫练 / 交练 / 焦练`。

任何包含这四个变体之一的输入都会触发唤醒。

### 3.2 动作词容错

- "深蹲" 必须精确匹配（短，不容易错）
- "弯举" 也精确匹配，但额外接受"哑铃" + 切换动词 = 弯举切换
- 如果用户说"切换动作"而没说具体动作，默认切到当前的对侧

### 3.3 模式词容错（最复杂）

百度 ASR 经常把"视觉加传感"切成各种谐音，例如"视觉加权战 / 视觉加杠杆 / 视觉加感 / 视觉加岗"等。系统的策略是：

- 维护一张约 15 条的**精确变体白名单**（如"视觉传感"、"传感模式"、"混合模式"、"融合模式"）
- 再做一个**泛启发规则**："视觉加 X" 只要不是"视觉加纯"，就当作视觉+传感意图

这样即便 ASR 把一个新词识别错了，系统也大概率不会卡住。

### 3.4 飞书近音容错

百度 ASR 经常把"飞书"切成同音字。系统维护了 11 条近音变体：`飞书 / 非书 / 飞出 / 非出 / 菲书 / 腓书 / 废书 / 飞输 / 非出去 / 飞出去 / 肥书`。

### 3.5 ASR 幻觉过滤

短的感叹词（`嗯 / 啊 / 哦 / 呃 / 嗯嗯 / 啊啊 / 哎`）和过短输入（小于 2 字）在 ASR 层就会被直接舍弃，**不会发给后端**。这避免百度 ASR 在背景噪声下随机识别出一两个字、造成系统乱响应。

## 四、播报与打断

- **正常播报**（应答、回复、组间总结、训练报告）：可以被任意新唤醒打断
- **违规警报**（动作不标准、代偿过多）：优先级最高，**即使在静音态也强制播一次**
- **TTS 串音保护**：系统播报时麦克风会暂时静音，避免 TTS 声波被自己的麦克风录回去触发误唤醒

## 五、飞书周报

飞书推送复用了上面提到的语音命令。除此之外，主页面还有：

- **手动按钮**：训练战报卡片、计划卡片、提醒卡片三类，点一下就触发推送
- **自动触发**：训练结束（达到目标 rep 数或长时间无新 rep）会自动生成训练战报推送
- **dry run 模式**：用于线下检查卡片排版，本地预览不真正发送

飞书卡片包含：

- 训练总览：合格 / 违规 / 代偿次数、总训练时长、疲劳峰值
- 动作分布：深蹲 / 弯举 比例饼图
- 跨日趋势：最近 7 天训练量和疲劳曲线
- AI 点评：DeepSeek 根据本次训练 + 历史给出的文字总结
- 下一次建议：基于疲劳和动作偏向的建议

外网不可用时，所有按钮和命令仍然能触发，但会**降级为本地预览**：板端把卡片渲染成 HTML 弹窗显示在主页面，不真正发出。

## 六、降级策略

如果麦克风、扬声器、ASR 服务、飞书接入任一环节坏掉，系统都有可走的替代路径：

| 失败环节 | 替代方案 |
|---------|---------|
| 麦克风坏 | 主页面"手动录音"按钮，按住说话 |
| 百度 STT 不可用 | 主页面"文字输入框"，直接输入命令文本 |
| 扬声器坏 | 主页面"对话历史"区域可见所有教练回复的文本 |
| 飞书外网不通 | 自动转为本地卡片预览，仍可看完整内容 |
| LLM 超时 | 训练总结和战报回退到本地模板，仍包含完整数值 |

降级是**透明的**：用户不需要做任何切换，系统自动检测失败并走替代路径。
