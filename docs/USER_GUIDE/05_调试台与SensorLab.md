# 调试台与 SensorLab

板端日常使用看主页面就够了。**调试台**和 **SensorLab** 是给开发者和深度用户的两个面板：调试台用来看系统状态、服务健康、日志；SensorLab 用来看肌电波形、采集数据、训练自己的模型。

## 一、调试台

调试台是主页面的一个标签页，专门展示系统底层状态：

### 1.1 服务状态

- 视觉进程是否在跑、当前用哪个后端（本地 NPU / 云端 GPU）
- FSM 进程的当前状态（站立 / 下蹲 / 起立 / 弯举中）
- EMG 进程是否收到 UDP 数据、丢包率
- 教练进程是否在监听唤醒词
- LLM 最近一次调用的延迟和返回大小

### 1.2 系统信息

- CPU 温度（直接读板端 thermal_zone0）
- 内存占用、磁盘剩余
- 网络连接情况
- SSH 隧道（如果开了云端模式）的活动状态

### 1.3 日志

按服务过滤的近 N 行日志，支持：

- 全部日志 / 视觉 / FSM / EMG / 语音 / 流服务
- 关键字搜索
- 实时跟随（类似 `tail -f`）

适合在演示出问题时快速定位是哪一层失败。

### 1.4 管理页

调试台只读。如果需要重启某个服务、清理共享内存、强制重置 session，可以打开管理页（`/admin`）做操作。

## 二、SensorLab

SensorLab 不是板端服务，而是**跑在本机**（开发笔记本）的独立工具。它通过 USB 串口或 Wi-Fi 直连 ESP32 肌电传感器，提供一个完整的"采集 → 标注 → 训练 → 部署"工作台。

### 2.1 启动方式

```bash
python tools/ironbuddy_sensor_lab.py --board-ip <BOARD_IP>
```

启动后浏览器访问 `http://127.0.0.1:8766/`。

### 2.2 主要面板

#### 实时波形面板

- 4 通道原始 ADC（约 1000 Hz 采样）
- 4 通道带通滤波后波形（10-500 Hz）
- MDF（中值频率）和 MNF（平均频率）实时计算
- RMS 包络和归一化激活值

实时波形是最有用的诊断面板：贴片接触不良会立刻在原始波形上看到平坦或饱和；MDF/MNF 的下降趋势可以反映肌肉疲劳。

#### 数据采集面板

- 选择动作（深蹲 / 弯举 / 自定义）
- 输入"标准 / 代偿 / 错误"标签
- 点击录制，板端 FSM 和 SensorLab 同时记录
- 一次录制结束生成一个 `.npz` 文件，包含骨架 + 肌电 + 标签

#### 模型训练面板

- 列出已有的训练数据集
- 选择模型类型（GRU 三分类、NCC、其他）
- 配置训练超参（epochs、lr、batch size）
- 训练结束直接生成 `.pt` 文件并自动注册到模型库

#### 部署面板

- 上传训练好的 `.pt` 到板端
- 触发板端 FSM 进程热重载（不需要重启）
- 通过实时数据回灌验证新模型表现

### 2.3 为什么单独跑在本机

板端 RK3399ProX 上跑 PyTorch 训练**太慢**（NPU 只支持推理）。SensorLab 让模型训练在开发笔记本的 CPU 或 GPU 上完成，训练好的 `.pt` 量化后再下发给板端。

## 三、典型工作流

### 3.1 调试一次失败的演示

1. 主页面看现象（动作没计数 / EMG 波形是平的 / LLM 没响应）
2. 切到调试台，看是哪个服务挂了 / 哪条日志在报错
3. 必要时打开管理页重启对应服务
4. 验证现象消失，回到主页面继续

### 3.2 采集自己的数据训练个人模型

1. 启动 SensorLab，连到板端
2. 实时波形面板检查肌电信号质量
3. 数据采集面板录制 30-50 次动作，含标准 / 代偿 / 错误三类
4. 模型训练面板训练 GRU 或 NCC 模型
5. 部署面板上传到板端，热重载
6. 主页面切到视觉+传感模式，验证新模型识别效果

完整工作流约 1-2 小时，不需要任何外部服务器。
