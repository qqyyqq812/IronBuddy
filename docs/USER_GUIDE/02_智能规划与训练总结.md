# 智能规划与训练总结

本章展开介绍智能训练计划的生命周期：从计划怎么生成，到训练过程中组间总结何时出现，再到训练结束后的整体战报。

## 一、为什么把这件事交给 LLM

传统健身 APP 的"训练计划"是静态模板：选个目标（增肌 / 减脂 / 力量），按表照搬。问题是它**完全不考虑**当下用户身体状态：

- 昨天有没有练？练得是否到位？
- 今天累计疲劳已经到哪一档？
- 上一次的代偿动作是不是偏多？
- 用户最近几天偏好什么动作？

IronBuddy 把这些上下文打包成 prompt 发给 DeepSeek，让 LLM 在**连续空间**而不是离散模板里给出建议。这是把"AI 健身教练"做到位的关键设计。

## 二、智能计划生成

主页面"智能规划"区域是整个流程的入口。点击"生成今日计划"按钮，系统按以下顺序执行：

### 2.1 上下文收集

板端会查询本地数据库，把以下信息汇总成一段 prompt 上下文：

- 最近 7 天的训练记录（动作 / 组数 / 合格率 / 疲劳曲线）
- 当天已累积的疲劳积分
- 用户在设置面板里的偏好（疲劳上限、习惯动作、训练时长）
- 系统状态（视觉后端、模式、传感器是否在线）

### 2.2 DeepSeek 流式调用

- 调用 DeepSeek REST API，开启 SSE 流式输出
- 前端实时渲染"思考链"：你能看到模型在产出每一个 token 时的中间过程
- 默认超时 30 秒，超时自动取消请求并退回降级路径

### 2.3 计划卡片渲染

LLM 输出后，系统把结构化的计划渲染为卡片：

- **动作**：深蹲 / 弯举（或混合）
- **组数 × 每组次数**：例如 3 组 × 10 次
- **目标疲劳积分**：基于当前累积值计算
- **建议强度**：轻松 / 标准 / 大重量
- **注意事项**：例如"昨天代偿多，今天降组数关注角度"

### 2.4 用户采纳

点"采纳计划"按钮，系统会：

- 把计划写入板端共享内存，FSM 进程立刻读到并切换到训练态
- 自动按计划首动作设置主页面动作开关
- 在状态栏显示"训练中 / 第 X 组 / 第 Y 次"

如果用户说语音命令"开始训练"也能达到同样效果，详见语音控制章节。

### 2.5 离线降级

DeepSeek 不可用时（外网断、配额满、API key 没配），系统会自动走**预设模板池**：

- 模板按 `(动作, 当日累积疲劳档位)` 索引
- 文案是预先撰写的中文段落，包含组数、次数、注意事项
- 用户在前端**看不出区别**，仍然有完整计划卡片

## 三、训练过程中的组间总结

训练态启动后，FSM 开始正常计 rep。每完成一组（达到目标 rep 数、或用户主动结束、或长时间无新 rep）系统会自动触发**组间总结弹窗**。

### 3.1 触发时机

- 达到目标 rep 数 → 立刻弹
- 用户语音说"结束本组" → 立刻弹
- 训练态持续 10 分钟没新 rep → 视为离开训练，弹"组结束并暂停"

### 3.2 总结内容

弹窗包含：

- 本组合格 rep 数 / 违规 rep 数 / 代偿 rep 数
- 本组平均最低角度
- 本组疲劳积分变化（这组贡献了多少）
- LLM 生成的一句话点评（"角度到位，但代偿次数偏多，下组注意收紧核心"）
- 建议的下组动作 / 组间休息时间

### 3.3 弹窗行为

- 弹窗在 5 秒后自动消失，不阻塞主流程
- 用户可主动点"我知道了"立刻关闭
- 关闭后内容仍可在"对话历史"里回看

### 3.4 离线降级

LLM 不可用时：

- 文字点评回退到**规则引擎**：根据合格率 / 代偿数 / 疲劳变化在模板池里挑一条
- 数值部分（次数、角度、疲劳变化）全部本地实时计算，不受外网影响

## 四、训练结束后的整体战报

完成所有组、或用户主动停止训练后，系统生成**训练战报**。这是一份比组间总结更详细的报告：

- 整次训练的所有组数据汇总（动作 / 组数 / 每组次数 / 合格率）
- 单次训练的疲劳曲线（rep 级，可视化）
- 与最近 7 天的对比（合格率变化、疲劳累计趋势）
- AI 给出的整体点评和下一次训练建议
- 可一键推送到飞书会话（详见语音章节）

战报在主页面"数据"标签和数据库页都可回看，永久保存。

## 五、和数据库的关系

整个计划生命周期都会**实时落库**：

- 计划生成时往 `llm_log` 表写入 prompt 和 response
- 每个 rep 完成后写 `rep_events` 表
- 训练结束触发 `training_sessions` 表的 end_ts 更新
- 每日凌晨自动汇总成 `daily_summary` 表

这样保证训练结果可追溯、可复盘、可对外汇报。详见 [03 数据库页](03_数据库与训练趋势.md)。
