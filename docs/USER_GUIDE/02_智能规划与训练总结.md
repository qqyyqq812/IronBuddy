# 02 智能规划与训练总结

本章说明智能规划和训练总结的用户路径。它关注页面怎么操作、什么时候出现
总结，以及总结结果如何用于下一组训练。

## 功能入口

智能规划集中在主页面完成。系统会根据当天状态、历史训练、疲劳目标和当前
运动模式生成训练建议；训练过程中，页面会在组间或结束时展示总结。

- 训练计划接口：`/api/training_plan/daily`
- 采纳计划接口：`/api/training_plan/daily/accept`
- 组间总结接口：`/api/llm/summary`
- 训练报告接口：`/api/training_report`

## 规划流程

现场建议先演示可控路径，再演示真实训练路径。这样即使外部 LLM 不稳定，
也能保留页面闭环。

1. 在主页面选择运动类型。
2. 生成当天训练计划。
3. 检查组数、目标疲劳和建议强度。
4. 采纳计划，让页面进入训练态。
5. 开始第一组动作，观察状态和计数更新。

## 训练总结

训练总结有两类展示：组间总结和最终总结。组间总结用于指导下一组动作，
最终总结用于说明本次训练完成度。

- `kind=set`：一组结束后的短总结。
- `kind=final`：整次训练结束后的最终总结。
- `mock=true`：本地演示或离线验证时可使用的 mock 路径。
- `timeout_s`：限制外部 LLM 等待时间，避免现场长时间卡住。

## 验收要点

验收时不只看页面是否弹窗，还要看弹窗内容是否来自正确阶段。

- 第一组结束后出现总结弹窗。
- 弹窗会自动消失，主流程不被永久遮挡。
- 最终总结能区分本次训练总次数和完成情况。
- 外部 LLM 不可用时，页面仍有可解释的降级文本。
