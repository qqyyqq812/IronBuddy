# 06 硬件部署

本章说明板端、云端和传感器的部署关系。它只写可公开的结构和占位符，不写
真实账号、密钥或会话信息。

## 拓扑

IronBuddy 的现场部署通常包括浏览器、本机、RK3399ProX 板端、ESP32 传感器
和可选云端视觉服务。

```text
Browser
  |
  | http://<BOARD_IP>:5000
  v
RK3399ProX board
  |-- Flask UI and API
  |-- vision / FSM / EMG / voice processes
  |-- SQLite database
  |
  | UDP or local network
  v
ESP32 EMG sensor

Optional:
RK3399ProX board <-> SSH tunnel <-> Cloud pose service
```

## 板端部署

板端运行主页面、数据库、服务控制和实时状态接口。实际部署路径以现场环境
为准。

- 项目路径：`/home/toybrick/embedded-fullstack`
- 主服务：`streamer_app.py`
- 视觉进程：`hardware_engine/ai_sensory/*`
- FSM 进程：`hardware_engine/main_claw_loop.py`
- 语音进程：`hardware_engine/voice_daemon.py`
- 共享状态：`/dev/shm/*.json`

## 云端部署

云端视觉或 LLM 只作为可选增强。手册中统一使用占位符，避免泄露真实连接
信息。

- 云端主机：`<CLOUD_HOST>`
- SSH 端口：`<CLOUD_PORT>`
- 本地转发端口：`<LOCAL_TUNNEL_PORT>`
- 云端服务地址：`http://127.0.0.1:<LOCAL_TUNNEL_PORT>`

## 传感器部署

EMG 传感器通过无线网络把数据送到板端或本机调试页。高频数据优先使用 UDP，
避免实时波形被重传阻塞。

- 采样端：ESP32 或等效采集设备。
- 接收端：板端 UDP 服务。
- 前端展示：主页面 EMG 区域或 SensorLab。
- 验收重点：波形刷新、通道映射、MVC 归一化和断连提示。

## 启动检查

部署完成后按从底层到页面的顺序检查，不要直接从最终页面倒查。

1. 检查板端网络和 `<BOARD_IP>`。
2. 检查 Flask 主服务。
3. 检查 `/state_feed` 和 `/api/muscle_activation`。
4. 检查数据库页面。
5. 检查语音、飞书或云端增强项。
