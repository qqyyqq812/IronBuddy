# 硬件部署

本章说明 IronBuddy 在板端、云端、传感器三块的部署关系，以及怎么把系统跑到自己的硬件上。本章不写真实密钥、IP、token，所有具体值都用占位符表示。

## 一、拓扑

一套完整部署包含以下角色：

```text
浏览器 (用户笔记本 / 手机)
    │
    │ HTTP
    ▼
RK3399ProX 主板  ◄──────  USB 摄像头
    ├── Flask 主服务 :5000
    ├── 视觉推理进程（本地 NPU 默认 / 云端 GPU 可选）
    ├── FSM 进程（动作识别 + rep 计数 + 疲劳积分）
    ├── EMG 服务（UDP 接收 + FFT 特征提取）
    ├── 语音守护进程（百度 ASR + TTS + 命令路由）
    ├── SQLite 数据库（WAL 模式）
    │
    │ UDP 8080
    ▼
ESP32 肌电采集器 (4 通道)

可选：
板端 ─────►  SSH 隧道  ─────►  云端 GPU 服务器
                              └── RTMPose HTTP 服务
```

## 二、板端

板端是整个系统的核心。所有判定、计数、疲劳积分、数据库都在这里完成。

### 2.1 硬件

- **Toybrick RK3399ProX**：6 核 ARM big.LITTLE CPU + 3 TOPS NPU
- 4 GB 内存 / 32 GB eMMC
- USB-A 接 摄像头、HDMI 接显示器（可选）
- Wi-Fi 或网线接局域网

### 2.2 软件栈

- Debian 10 (官方 Toybrick 镜像)
- Python 3.7（NPU SDK 限制，**禁用** Python 3.7 不支持的语法）
- RKNN runtime 1.7.5
- Flask + Gunicorn + WSGI
- SQLite (内置)
- ALSA (音频)

### 2.3 启动顺序

板端开机后按以下顺序拉起：

1. 网络上线（DHCP / 静态）
2. NPU runtime 加载视觉模型
3. EMG UDP 监听
4. FSM 进程启动
5. Flask 主服务监听 :5000
6. 语音守护进程开始监听唤醒词

systemd 已经配置好启动依赖，正常开机后约 60 秒系统就绪。

### 2.4 配置文件

板端 `.env` 文件保存所有外部服务凭据：

- DeepSeek API key
- 百度 AipSpeech app id / api key / secret key
- 飞书应用 id / secret / 默认会话 id
- 云端 GPU SSH 信息（如果使用云端后端）

`.env` **不入版本控制**，由部署时手动放到板端 `/etc/ironbuddy/.env`。

## 三、ESP32 肌电采集器

肌电采集是一个独立的小硬件模块，单独烧录、单独充电。

### 3.1 硬件

- **ESP32-S3** 主控
- 4 通道差分肌电前端（INA333 + 滤波）
- 锂电池 + 充电管理
- 自粘电极片

### 3.2 配对流程

1. 板端运行配对程序，输出"等待 ESP32 上线"
2. 给 ESP32 上电，固件自动扫描本地局域网，找到板端的 UDP 8080
3. 发送握手包，板端确认后写入设备 MAC 到白名单
4. 以后每次上电会自动重连，不需要重新配对

### 3.3 信号路径

ESP32 → ADC 采样（1 kHz）→ Wi-Fi UDP → 板端 EMG 服务 → 滤波 / FFT → MDF/MNF + RMS → 共享内存

### 3.4 贴片要点

- 4 个通道：主发力肌、对侧肌、协同肌、参考点
- 贴片前用酒精擦皮肤、剔除浅层毛发
- 电极间距约 2 cm，沿肌纤维走向

## 四、云端 GPU（可选）

如果要用更高精度的 RTMPose 替代本地 YOLOv5，需要一台外网可达的云服务器（带 GPU）。

### 4.1 服务器要求

- Ubuntu 20.04 或 22.04
- NVIDIA GPU（RTX 系列即可）+ CUDA 11+
- Python 3.10+
- 公网 IP 或反向代理可达

### 4.2 安装

```bash
git clone <repo> /opt/ironbuddy
cd /opt/ironbuddy/hardware_engine/ai_sensory/cloud_deploy
pip install -r requirements.txt
bash start.sh
```

服务监听 `127.0.0.1:6006`，提供 `/infer` HTTP 端点。

### 4.3 板端连接

板端通过 SSH 隧道把云端 `:6006` 映射到本地：

```bash
ssh -N -L 6006:127.0.0.1:6006 <user>@<cloud-host>
```

之后板端视觉进程访问 `http://127.0.0.1:6006/infer` 即可。

主页面"视觉后端"下拉框切到云端时，板端会自动检查隧道是否在，不在则尝试启动；启动失败提示用户检查 SSH 凭据。

## 五、启动检查清单

部署完一台新板子，按以下顺序验证每一层：

1. **网络**：ping 板端 IP 通
2. **Flask**：浏览器打开 `http://<BOARD_IP>:5000/` 看到主页面
3. **视觉**：主页面视频区有实时画面，骨架在动
4. **FSM**：做一个动作，主页面 rep 计数加 1
5. **EMG**：摸一下电极，主页面肌电波形有变化
6. **语音**：说"教练"，听到"嗯"应答
7. **LLM**：点"生成今日计划"，看到流式输出
8. **飞书**：手动点"飞书战报"按钮，确认推送或本地预览
9. **数据库**：训练几个 rep 后打开 `/database` 看到记录

每一层都通过后，系统才算完整可用。某一层挂掉时，其他层都还能独立工作。
